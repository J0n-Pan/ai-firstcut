> 判据层面的设计说明在 `docs/模型判断依据.md`。

## D-01 rebase 走全量重跑，版本对比不可比（P0）

### 现象

剪辑台「收紧气口」重跑（`kind: "rebase"`）后，不只气口变了，**文字裁决也全变了**：
同一素材的 v1（默认档）与 v2（收紧档）剪点、卡片数量、卡片类型都不同，用户无法判断差异是"气口造成的"还是"语义判断变了"。

### 证据（C0853，`episodes/ui-20261022_C0853-032619`）

| | v1 默认档 11:27 | v2 收紧档 11:35 |
|---|---|---|
| 启动参数 | `--cut-only` | `--cut-only` + `XUNJIAN_REBASE_TO=2` + `XUNJIAN_TIGHT_BREATH=1` |
| 转写 | 调用 ASR 一次 | **重新调用 ASR**（`run-usage.asr` 90.47s / ¥0.0072） |
| 语义裁决 | LLM 2 次 | **重新调用 2 次**（filler 1 + redundancy 1 / ¥0.0057） |
| cuts | 5 段 | 5 段，但第三段从 `59.36–62.38` 变成 `56.88–62.38` |
| 卡片 | 2 张（slip-weak #3、#9） | 3 张（多 paraphrase-weak #13） |

代码位置：`scripts/studio-server.mjs` 的 `startCut()` 在 rebase 分支只注入
`XUNJIAN_REBASE_TO` 与 `XUNJIAN_TIGHT_BREATH`，**没有 `XUNJIAN_REUSE_ASR`**；
`redundancy-verdicts.json`、`filler-map.json` 只写不读，没有缓存复用路径。

### 影响

- 用户看到「收紧气口」按钮，预期是「只改停顿」，实际拿到的是「换一次随机结果」。
- 任何 A/B（默认 vs 收紧、换模型、改单个参数）都失去可比性。
- 每点一次多花一次 ASR + LLM（约 ¥0.013/次，见 v2 的 `run-usage.json`）。

### 修复方案

1. `startCut()` 的 rebase 分支注入 `XUNJIAN_REUSE_ASR=1`（现成开关，条件：`raw-segs.json` / `raw-asr.wav` 比源片新）。
2. 新增 `XUNJIAN_REUSE_VERDICTS=1`（rebase 时默认开启）：
   - `run.mjs` 在调用语义扫描前，先读 `redundancy-verdicts.json`；
   - 缓存键 = `sha1(prompt 模板版本 + 模型名 + 按序拼接的单元文本)`；
   - 命中则直接用，未命中原样调用 LLM 并回写；
   - `filler-map.json`、`verbatim` 同理。
3. 缓存文件里记录 `promptVersion`，判据改动时版本号 +1，旧缓存自动失效。

### 验收标准

- 同一工程连跑两次默认档：`cut-plan.cuts`、`review-queue` 逐字节一致。
- 再跑一次收紧档：**文字相关剪点与卡片完全一致**，差异只出现在 `segs` / `tight` 字段。
- `run-usage.asr` 在 rebase 时为 0。

### 复现

```bash
# 第一次（默认）
XUNJIAN_USAGE_LOG=... node firstcut/run.mjs <src> --name t1 --cut-only
# 第二次（收紧）—— 当前会重新转写 + 重新裁决
XUNJIAN_REBASE_TO=2 XUNJIAN_TIGHT_BREATH=1 XUNJIAN_USAGE_LOG=... \
  node firstcut/run.mjs <src> --name t1 --cut-only
# 修复后应只差 tight 字段
```

## D-02 tight-breath 无单元级存活护栏，低音量连贯句被剪成碎片（P0）

### 现象

卡片标注「护栏拦住 · 保留」，实际成片里这句话被剪成碎片；卡片区间同步缩水。

### 证据（飞书 `episodes/ui-飞书20261028-180650-101141` #20）

- 原句 99.02–104.76（5.74s）「补充一点，我们的借款怎么可以怎么练习这个？」
- 卡片显示 101.23–103.99（2.76s），被 `clipReviewItems` 按最终保留段重切成 4 个碎片
- `keptText = "借款么练"`（4/22 字 = **21%**），全片唯一一处存活率 <60%（其余最低 72%）
- `tight-breath.json`：`minRunSec=0.06`、`guardSec=0.06`、`thresholdDb=-25.3`
- 同一素材 17:54 工程未开收紧（`tight=null`），该句存活 84%

### 根因

`tight-breath.mjs` 是纯能量掩膜，拿全片门限逐个静音段剪，**完全不看语义单元**。
这句话压着音量说，字间只有 70–240ms 换气缝：
- 正常档 `silencedetect d=0.35` → 该句内只检出 2 处（0.36s、1.06s）
- 收紧档 `d=0.06` → 检出 14 处，逐个剪掉，每刀再内缩 60ms

全局安全阀 `maxShrinkRatio 0.55` 是整片级的（本次全片 135.46→115.85s，只剪 14%），对单句失效。

### 修复方案

1. `tightenSegs` 接受语义单元表（`SEG` + 卡片保留项），逐单元算存活率：
   - 某单元剪后存活 <60% → **放弃该单元内的 inner cuts**，只保留与相邻删除区重叠的边界修剪；
   - 存活率按「保留时长 / 原时长」算，有 `keptText` 时按字数算，取更严的。
2. tight 之后回写卡片：区间被剪 ≥90% 的卡片改标「实际已删 / 仅剩残片」并附原因，不再显示成「拦住」。
3. `tight-breath.json` 增加 `unitGuard` 统计（放弃了几处、省下多少秒）。

### 验收标准

- 飞书 18:11 工程 #20 存活 ≥90%，卡片区间仍为整句 5.74s。
- 全片 `savedSec` 下降不超过 1.5s（护栏只该放弃 inner cuts，不该放弃句间气口）。
- 17:54 / 18:11 两工程的 `review-queue` 文本与状态一致。

## D-03 语义裁决不可复现：同一素材、同一转写、同一模型，三次运行三种结果（P0）

### 现象

`llm.mjs` 已设 `temperature: 0`，但同输入多次调用仍得到不同的标签集合。
默认档与收紧档的判断差异，主因不是「档位」，而是「第几次运行」。

### 证据（C0853，同一份 `raw-segs.json`）

| 运行 | 输入 | verdicts | 54.83 句 | 57.83 句 | #3/#9 slip |
|---|---|---|---|---|---|
| v1（11:27） | 自己那次 ASR | 未留存 | 无标记 | 无标记 | 2 张 weak 卡 |
| v2（11:35） | 重新 ASR | 7 条 | paraphrase-weak 卡 | 删 | 2 张 weak 卡 |
| 本次默认档（12:03） | **复用 v2 转写**，`tight=null` | **5 条**（缺 #3/#9） | paraphrase-weak 卡 | 删 | **无（判 ok）** |

本次默认档与 v2 的 `cuts` 几乎逐字相同（`56.88` vs `56.875`），证明：

- **默认档具备与收紧档相同的语义判断能力**，v1 漏标不是「档位少了一步」；
- 差异来自 LLM 每次采样的标签集合不同（本次甚至比 v2 少判了两处 slip）。

### 根因

1. rebase 不复用裁决（D-01）→ 每次重跑都是新采样。
2. `temperature: 0` 在百炼上**不等于确定**：未传 `seed`，MoE 路由与批处理仍会带来差异。

### 修复方案

1. 先修 D-01 的裁决缓存 —— 这是版本可比性的底线。
2. `llm.mjs` 请求体加固定 `seed`（如 `seed: 20261110`），并记录在 `llm-usage.jsonl`。
3. 缓存键必须含 `promptVersion`，避免改判据后命中旧结果。
4. （可选）对高风险标签（`slip` / `paraphrase`）做**两次采样取交集**：两次都判删才自动删，
   否则进卡片。代价是裁决成本 ×2，可通过「只对问句/长句启用」控制。

### 验收标准

- 清空缓存后连跑 3 次默认档，`redundancy-verdicts.json`、`review-queue` 逐字节一致。
- 若仍不一致，说明 `seed` 无效，需退到「两次采样取交集」方案。

## D-04 默认档缺「连续同义提问」确定性判据（P1，已修 2026-11-10）

### 现象

「那老师您这个方法在哪里学呢 / 你老师到底有什么方法 / 呃呃老师你这个到底是什么方法呢」
连续三句问同一件事。当前只靠 LLM 判 `paraphrase`，模型漏判时默认档就静默保留。

### 根因

`paraphrase` 是 LLM 标签，没有确定性兜底。`question-cut.mjs` 只覆盖两类结构问题：
半截问句（句末缺中心语）与问句前缀卡壳（段内停顿后重起头），
都接不住「多个完整问句、同一疑问焦点、后句最完整」这种跨句重复。

### 修复方案（草案，需先验证不误伤）

新增 `firstcut/askchain.mjs` → `detectAskChains(units, opts)`：

判据（全部满足）：
- 连续 ≥2 个单元都是问句（`looksLikeAsk`）；
- 共享疑问焦点：去掉疑问词后的实词集合有 ≥2 字交集（「方法」「在哪里」需分别建模，
  不能只看字面重合，否则「在哪里学」与「有什么方法」会被判成不同问题）；
- 相邻间隔 ≤ `maxGapSec`（建议 2.5s）；
- 后句字数 ≥ 前句，且后句包含前句的焦点词；
- 前句不含后句没有的独有信息词（如「哪里/在哪」是独有信息时**不删**）。

输出：删前保后，进 `same-question` 卡（默认 cut），并在 `keptText` 里保留证据。

**必须先跑 C0820 验证**：11-06 撤回过一版 `detectRepeatAsks`，因为把「自问自答」误判成重复追问。
新判据要求「后句仍是问句」，自问自答的后句是陈述句，应能区分。

### 验收标准

- C0853：57.83 句稳定被删（不依赖 LLM），54.83 句进卡不删。
- C0820：0 处误伤（自问自答全部保留）。
- C0777 / C0816 / C0779：剪点与当前基线逐字节一致。

### 实现结果（`firstcut/askchain.mjs`，2.7 步）

- **同义**：焦点类别集合相等 + 实词重合 ≥60% → 删前留后，不看长度。
  另有 `growRatio` 护栏：后句实词量 > 前句×2+2 时判为「答+新问」不删（C0820 自问自答）。
- **不同意义**：焦点不同但实词重合 ≥60% → 只进卡。
- **必须喂 `rawSegs`**：拆段会把 C0853 #13 切成两段、间隔 2.59s 直接断链，
  正当的 #12→#13 反而漏判（已实测复现）。
- 实测：C0853 #12 删 1.60s、#11 进卡；C0820 / C0777 / 飞书 / DJI 均 0 命中；
  C0779 的条件从句误报在 `related` 加重合率门槛后消失。

## D-05 低电平语音被气口剪成碎片（P0，已修 2026-11-10）

### 现象

整句压着音量说 → 气口/收紧气口把它当静音逐段剪掉，成片只剩几个较响的字，事后查不出是哪一刀。

### 证据

| 工程 | 句子 | 字级证据 | 结果 |
|---|---|---|---|
| C0793 `raw#8` | 这果免费送价值一千多万就不能说是吧 | 17 字连续覆盖 78.02–81.40，句内窗口 p90 比语音参考低 **19.6dB** | 字时长 **97%** 落在 `removed`，只剩 `[80.31,80.42]` 0.11s「就不」 |
| 飞书 101141 `raw#16` | 补充一点，我们的借款怎么可以怎么练习 | 99.02–104.76，低 **19.6dB** | 卡片显示 2.76s，`keptText="借款么练"`（21%） |
| DJI 结尾 | （无字底噪） | 89.23–90.63 共 1.39s，零个字，p90 低 **13.2dB** | 保留 1.4s 空白 |

### 根因与修复

气口与 tight 都只看能量、不看转写。**正确处理不是保护碎片，而是按整句判废、整段删干净**——
用户要的是「这句不要」，不是「这句留三个字」。

新增 `firstcut/speechmask.mjs`，在转写之后（步骤 2.6）插入一次复核：

- **基准**：各句段「0.5s 分窗 p90」的**中位数**（不是 `mean_volume`——它被大段静音拉低，
  DJI 全片 mean −35.5 而语音 p90 −31.5）。
- **低电平整句**：`ref − 窗口p90中位数 ≥ 15dB` 且 `ref − 最响窗口p90 ≥ 9dB`（防"半句正常"）→ 整段从 `segs` 扣除。
- **无字底噪**：保留段内连续 `≥1.0s` 零字 + `p90 < ref−12dB` → 整段扣除。
- 判废句不生成卡片（用户 2026-11-10 定），只在日志与 `cut-audit` 留 `lowlevel` 痕迹。

为什么不用 `p90−p10` 判"整句都低"：句内字间本来就有 0.15–0.3s 换气缝，p10 会被拉到 −50dB，
正常句与低电平句的跨度都是 10~15dB，该指标无区分度（实测 C0793 全片如此）。

### 验收（六工程实测）

| 工程 | 命中 | 余量 |
|---|---|---|
| C0793 | #8（19.6dB）、#9（19.9dB） | 未命中最高 9.0dB |
| 飞书 | #16（19.6dB）、底噪 96.99–99.02（21.5dB） | 未命中最高 1.9dB |
| DJI | 底噪 89.22–90.62（13.2dB） | 未命中最高 9.4dB |
| C0777 / C0816 / C0779 | 0 处 | — |

阈值 15dB 两侧余量 5.6dB 以上；`gapDropDb` 取 12 是因为 DJI 实测 13.2dB。

## D-06 半字收口剪掉疑问语气词（P2，未修）

### 现象

DJI `#2`「数学就不用背吗」成片变成「数学就不用背」——句末「吗」被 `trimCutsToVoice` 按
"只剩 0.24s < 50%" 判为半个字，整段剪掉，疑问句变陈述句。

### 未修原因

与 D-05 同属能量层，但影响面小（一句 0.24s），且修法需要区分"句末语气词"与"半个字"，

## D-07 元话语与孤立单句无判据（P1，已修 2026-11-10）

### 现象

片头「单独录这一条」、片尾「没关系我就这样吧」「嗯ok我再单独录一条」语义完整、语法正确，
模型只能判 `ok`，于是既不删也不标记，直接进片。

### 修复

新增 `firstcut/metatalk.mjs`，两个独立判据，在 2.8 步执行：

| 判据 | 条件 | 处理 |
|---|---|---|
| **孤立句** | 离「正文主体」≥5s、自身 ≤5s、所在簇跨度 ≤5s | **默认删** + 进卡告知 |
| **元话语** | 片头 2 句 / 片尾 2 句、≤4s、与相邻 3 句实词零交集、命中词表 | **只进卡不删** |

两者都命中时**按孤立句处理**（先跑 isolated，`seen` 去重）——C0793 #0「现在备战其中」
既是录制说明又离正文 34.5s，留着就是一段突兀残句。

### 验收

| 工程 | 结果 |
|---|---|
| C0793 | #0 孤立句删 1.35s；#10 元话语进卡 |
| DJI | #0 元话语进卡（与 #1 紧接，不算孤立） |
| C0816 | #11「嗯ok我再单独录一条」进卡（基线里被模型判 offtopic 删掉，现在改为只进卡 → 成片 +2.26s） |
| C0777 / 飞书 | 0 命中 |

## D-08 卡片因区间被剪空而静默丢弃（P0，已修 2026-11-10）

### 现象（原判断有误，此处更正）

C0793 `raw#8` 模型判了 `slip` 并**成功生成了 `slip-noref` 卡片**，但 `review-queue.json` 里没有它。
不是"没生成"，是 `review-clip.mjs` 的 `if (!allCuts.length) { dropped++; continue; }` 把它丢了：
该句 97% 的时长已被气口剪掉，`clipCuts` 把三个选项的区间都裁成空，于是整条被扔，**连日志都不打**。

### 修复

`clipReviewItems` 在 `!allCuts.length` 时保留原区间、清空 `options`、标 `alreadyRemoved: true`，
返回 `alreadyRemoved` 计数；`run.mjs` 在汇总行打印「其中 N 条区间已被气口/低电平整句删掉」。

### 验收

C0793 卡片 0 → 4（3 条标 `[已删]`）；C0779 1 条；飞书/ C0777 / C0816 均能在日志区分"真卡片"与"只读提示"。

## D-04 的补充：`related` 必须过重合率（2026-11-10 修复过程中发现）

初版 `related` 只要求「焦点不同 + 实词有交集」，在飞书素材上产生 **6 张废卡**：
「接下来考什么？／考阅读理解怎么去做啊？／是瞎做吗？／作文是随便编的吗？」——
这是**设问→回答→再设问**的教学递进链，不是同一问的重复。

已改为 `related` 也必须 `实词重合率 ≥ 60%`（与 `same` 同一门槛）。修复后：
- C0853 `#11→#12` 重合 1.0，仍进卡 ✅
- 飞书 6 张 → 0 张 ✅
- C0779 `#3` 误报（条件从句被 `looksLikeAsk` 判成问句）→ 0 张 ✅
