# 模型判断依据总表

> 适用版本：`feat/verbatim-live-align`（2026-11-03，含内嵌「段内多次起头」「短残句兜底」「切口不越界」三处修复）
> 代码入口：`firstcut/run.mjs`（粗剪）· `firstcut/verbatim.mjs`（逐字剪）· `firstcut/llm.mjs`（调用层）

## 0. 总原则

模型在这条流水线里**只表态，不落地**：

1. 模型输出的是**标签/意见**（cut / keep、drop 列表、fix 列表），不输出时间轴；
2. 真正的时间区间由确定性代码算（句段边界、字级时间戳、静音检测、护栏裁剪）；
3. 任何一次调用失败、超时、返回非法 JSON → **回退算法结果**，不阻断剪辑；
4. 所有判断都落盘到 `work/*.json`，可复盘「某句为什么没剪」。

## 2. 六个判断点

|---|---|---|---|---|---|---|
| 1 | 重说裁决 | `retake` | 有重说候选 | 句对 `cut/kept/sim/gap` | `cut-first` / `keep-both` | 开 |

### 2.1 重说裁决 `retake`

**为什么要有**：相似度只能证明"两句像"，不能证明"前一句是废的"。模型负责区分「说错重说」与「递进/并列/刻意排比」。

**候选怎么来**（确定性，`detectRetakes`）：相似度 ≥ `recallSim 0.6`、间隔 ≤ `recallGapSec 20s`、向后看 `recallLookAhead 8` 句。

**判据（提示词原文要点）**

- 判 `cut-first` **仅当**：后一句是前一句的重说或补全，前一遍明显是废的。
  - 前句说一半/说错，随即从头重说：「相反的一个脾气」→「相反的一个脾气一点就着」；
  - 措辞微调后再讲一遍：「当孩子看到爸爸的脸是这个」→「当孩子看到爸爸脸是松的」。
- 判 `keep-both`：两句语义不同（递进/并列/补充）、两句完全相同、**任何拿不准**。

**代码护栏（模型说了不算数）**

| 护栏 | 规则 |
|---|---|
| 确定性命中直采 | LCP 开头连续 ≥6 字且间隔 ≤2s，或整句相似度 ≥0.9 且间隔 ≤20s → 不看模型直接剪 |
| 换说法护栏 | 保留文本是剪除文本的**真后缀** → 不剪（前一遍更完整） |
| 互斥重说对 | 同时出现「剪A留B」「剪B留A」→ 只保留较早一条，避免 A、B 一起消失 |
| 跨度告警 | 单条 >6s 只告警，不自动改 |
| 切口语义 | 各外扩 0.05s，最短 0.3s，间隔 ≤0.1s 合并 |

落盘：`work/retake-report.json`

### 2.2 语气词裁决 `filler`

**分工**：tier1 纯语气词（嗯/呃/唉/哦…）**不过模型**，前面有停顿就直剪；tier2 同形异用词（这个/那个/就是/然后/那么/其实/对吧/是吧）才交模型。

**判据（提示词原文要点）**

- 「这个」「那个」判据完全相同，只看两件事：**是否指代具体对象**、**删掉后句子是否通顺**。
- 判 `cut`：犹豫/找词时顺口带出、删后完整通顺且不指代；独立插入语；同句反复出现的垫词。
- 判 `keep`：回指前文（对照 `prev` 上一句）；指示代词 + 具体对象（这个情况/那个脑区）；**名词+这个+名词的同位结构**（记忆这个开关）；句首/句尾的「就是」表判断；「其实/然后/那么/对吧」承载语义；句首删后缺成分；**任何拿不准**。

**代码护栏**

| 护栏 | 规则 |
|---|---|
| 句首/句尾实义 | `就是/然后/那么/其实/所以/但是/因为/而且/如果/对吧/是吧` 落在段首或段尾 → 不剪 |
| 指示结构 | 「这个/那个」后接 事儿/事/东西/时候/地方/人/话/问题/情况/样子/感觉/状态 → 不剪 |
| 独立成说 | 其余 tier2 必须前后都有 ≥0.12s 停顿 |
| 留白 | 切口两侧合计留白 < `minGap` → 不剪（删了是硬拼） |
| 不落队列 | 模型判删但被上面任一条拦下 → 按「保留」处理，只写日志，不再逐条问用户 |

落盘：`work/filler-report.json`

### 2.3 语义冗余扫描 `redundancy`

**覆盖范围**：整片逐句（含片头片尾）一次送审。这是唯一能看到「跨句语义」的通道。

**标签定义**

| 标签 | 含义 | 落地 |
|---|---|---|
| `ok` | 保留（拿不准一律 ok） | — |
| `offtopic` | 片头寒暄/片尾告别/完全无关插话 | 仅片头 2 句、片尾 2 句可剪 |
| `slip` | 口误：说错/卡住/没说完，后一遍才说对，且没有完整重说 | 需 `keepId` 指向改正句（同句内改正填 null） |
| `paraphrase` | 换说法重说，意思相同用词不同 | `keepId` 必须**向后**且有效 |
| `filler` | 句内夹了语气词 | **不整句删**（交给词级通道） |

**判定纪律（写进提示词，用来压制模型的过度删减）**

1. 宁可漏剪，不要错剪；每条非 ok 都要能说清"删了观众不会觉得少了什么"。
2. **转写错误不是删除理由**：读不通、缺主语、同音错字一律 `ok`；只有文本里能看到前后两版措辞才算口误。
3. **论据不是 offtopic**：第一人称经历/资历/成果只要在支撑论点，必须 `ok`（不得以"冗余背书"为由删）。
4. **多次重复**：最后一遍的每一句都 `ok`；前面几遍的每一句都要标删；`keepId` 统一指向最后一遍第一句；"最后一遍"按内容完整判定，不按时间。
5. `offtopic` 只出现在前 2 句 / 后 2 句；中段一律 `ok`。
6. 6 字以内且下句以「第一个/第二个/首先/其次/那么/就/才/而/因为/所以」开头 → 本句是前件，标 `ok`。
7. 一条视频正常只需删 2~6 句。
8. **问答体的提问是内容骨架**：围绕主题的提问（"那老师到底有什么方法呢""真的这么简单吗"）一律 `ok`；
   删掉提问，回答就变成没头没尾的独白。只有问吃饭/天气/私事这类与主题无关的才算 offtopic。
9. **slip 必须能指出两版措辞**：`reason` 里写不出"前一遍说了什么、后一遍改成了什么"，就说明看到的只是
   转写错误 → 标 `ok`。"读不通 / 是病句 / 转写错误 / 缺主语"不是 slip 的理由。

**代码护栏**

| 护栏 | 规则 |
|---|---|
| `filler` 不整句删 | 语气词走词级切除 |
| offtopic 位置 | 中段 offtopic → 不剪，转「待确认」卡片 `offtopic-mid` |
| **片头口令分离** | 片头 offtopic 句段里含开机口令（等一下/三二一/开始念/开始录）→ 只删口令前缀，正文保留；口令后若紧接 ≤6 字同头半截（「我家背单」→「我家孩子背单词」），一并跳过 |
| **片头多次起头分离** | 片头 offtopic 句段其实是同一句连起 ≥3 遍（`detectMidRestarts`：≥5 字短语跨 ≥3 次起头复现）→ 只删到最后一遍起头之前，保留结尾正文。实测 C0816 三遍「再比如说数学」后接开场论证，模型按"试音堆叠"整段判 offtopic，会把开场第一个论点一起删掉 |
| **片头起头兜底（禁止静默整段删）** | 上一道因几何守卫不满足而没接住时（切口 >12s / 尾部 <12 字），只要段内仍有 ≥2 遍起头证据，就**不整段删**，改弹 `head-restarts` 三档卡（只删前几遍 / 整段删 / 保留）。全库目前 0 例，是对同一种误判的封口 |
| **提问保护** | 中段 offtopic 且是问句（吗/呢/吧 结尾或有疑问词）→ 不剪、**不进待确认**（问答体的提问是内容骨架）；问句因太短被 `paraphraseMin` 挡下时，同样只记日志、不弹卡 |
| **问句前导卡壳** | 问句 + 跳过句首语气词后的 2 字短语在 12 字内再现 → 只删卡壳那截（实测 59.63–62.38 删「呃老师那到底呃呃」，保留「老师你这个到底是什么方法呢」） |
| **slip 重说证据** | **不看理由里的用词**，只看文本结构，三条任一成立即允许整段删：① 与 `keepId` 句有 ≥6 字连续公共串（同一句被重说）；② 本句内部有 ≥4 字重复片段（说了一半又从头来）；③ 与 `keepId` 句开头有 ≥4 字公共前缀（同一句从头重说）。三条都不成立 → `slip-weak` 待确认。另：完整问句（？结尾）且与 `keepId` 句无 ≥4 字公共措辞 → 静默保留（那是另一句提问） |
| 重来版保护 | `DUP_HEAD` 里的句子（重说链的最终版首句）一律不删 |
| 收尾呼应 | 后 30% 且与开场前两句有 ≥8 字公共片段 → 视为总结，转 `echo-tail` 待确认 |
| 单句跨度 | > `maxSegSec 20s` 直接忽略 |
| 长 slip 子切口 | >16 字时依次尝试：句首短语再现有锚点 → 下一句完整重说 → 段内 5 字短语 ≥3 次 → 段内 7 字重来 → 末分句动词悬空；全不命中转 `slip-noref` 待确认 |
| paraphrase 方向 | `keepId` 必须 > 当前 id 且间隔 ≤25s，否则忽略（`paraphrase-dir` 待确认） |
| paraphrase 下限 | 被删句 ≥8 字且 ≥1.5s（几个字的半句不算一遍） |
| 前件依赖 | 保留句以「第一个/首先/那么/而/因为…」开头 → 被删句是它的前件，禁止删 |
| 孤立设问 | 中段短设问只有下文 2.5s 内跟上才放行 |
| 总量 | 删除总时长 ≤35% 全片、连续删除 ≤6 句，超限整批放弃 |

**结构路由（2026-11-04，解决两条通道互相打架）**

两条通道对同一段各给一个结论时，切口是**叠加**而不是覆盖：语义通道判得更宽（整段 offtopic）就吞掉起头通道判得更细的那一刀。实测 C0816 #0：`redundancy` 判 offtopic 整段删 `[0.03,10.49]`，`inner-restart` 对同一段判 `drop:[0,1]` 只删 `[2.61,5.77]`，合并后前者赢，开场第一个论点被删掉。

规则：

| 步骤 | 规则 |
|---|---|
| 路由条件 | `detectMidRestarts` 命中 **≥3 遍起头**（2 遍的段不路由 —— 起头通道有首段保护，两遍里唯一可删的那遍会被挡掉，路由等于放弃删除） |
| 送审 | 句段**仍留在 payload 里**（上下文不能丢），只多一个 `handled:"restart"` 标记 |
| 回收 | 该段语义判决**不入账**；模型原始判断写 `llm-shadow.json` |
| 不做撤销 | 送审时要求模型对这类段原样标 `ok`，这个 `ok` 是服从指令的产物、不是判断，**不能拿它撤销路由** —— 否则会出现"模型不判了 → 路由撤销 → 起头通道也跳过"，两个通道都空转（实测第一版踩过：成片首段留着「那端的补助是嗯数学吧」） |
| 口径 | `maxRatio` 分子只算语义通道自己的判定；结构路由的删除是确定性的，不受该断路器约束 |

全库 37 份素材（973 句段）实测：命中 3 段（C0816 #0、c0777 #7、C0820 #14），全部是"少删"（合计 −24.8s），其余 7 段零变化。

落盘：`work/redundancy-verdicts.json`（含 `routed` 字段）+ `work/llm-shadow.json`（被路由段的语义判决与撤销记录）

### 2.4 段内多次起头 `inner-restart`

**为什么单独开一条**：一句话起了 3~4 次头、间隙只有 0.3~0.7s，没到切句阈值，ASR 把几遍并成同一句。此时「段间重说」看不见、「段内假起头」要求重来点落在段首 12 字内，也看不见。

**候选（确定性，`detectMidRestarts`）**：句段 ≥20 字；按 ≥0.3s 停顿切出 ≥3 次起头；同一 ≥5 字短语在不同起头里复现。

**判据（提示词原文要点）**

- 作废起头：说到一半自己打断，缺宾语、断在「有没有/这个/的/就是」，紧接着下一段用同一个开头重说；
- 完整的一遍：有完整主谓宾、单独拿出来就是通顺一句 → **哪怕后面又说了类似的话也必须保留**；
- 只删"被后面更完整一遍取代"的那几段。

**代码护栏**

| 护栏 | 规则 |
|---|---|
| 首尾保护 | 末段永不删；首段默认保护，但**废起头可删** —— 首段不含那个重复短语、且 ≤8 字（「那端的补助是嗯」7 字、「那看到孩」4 字），说明它压根没说到正文，留着只会在成片开头挂一句断头话。c1 #14 那种 20 字完整首遍仍受保护 |
| 剩余长度 | 删完剩余 ≥12 字 |
| 单次时长 | 0.3s ≤ 删除 ≤12s |
| 短语留存 | 触发候选的那条 ≥5 字短语必须仍有一份留在保留段里 |
| 兜底 | 找不到 LLM 时不做任何删减 |

落盘：`work/inner-restart.json`

### 2.5 字幕错字纠错 `asrfix`（默认关闭）

**判据**：只把错字改成**同音/近音**字；严禁改写、润色、增删、调序；读得通就不改；`glossary` 仅供参考。

**代码护栏**：`id` 必须有效 → 长度差 ≤2 字 → 编辑距离 ≤ `maxEditPerLine 8` → 拼音相似度 ≥ `pinyinSimMin 0.5`（`pypinyin` 独立校验；校验不可用则本批全部丢弃）。

开关：`rules.corrections.enabled` 或 `XUNJIAN_CORRECTIONS=1`。落盘：`work/asr-fixes.json`

### 2.6 逐字剪填充词扫描 `fillerscan`（仅「逐字剪」）

**只报两类**：无信息量的指示代词 / 句首垫词（这个/那个/这样一个/那么/那，后面没有具体名词、只是顺嘴起头）、无意义口头禅（就是说/然后/其实/你知道吧/说白了/对吧/怎么说呢/反正/什么的/之类的）；外加句中卡壳的迟疑音（呃/嗯）。

**不要报（演绎）**：句末 / 短语末的语气词 啊/呀/嘛/呗/吧/呢/哦/噢/唉/哎 —— 这些是口播里的语气、情绪、提问腔，删掉人物会变生硬；程度用法的「那么」（那么简单/那么高）也不报。

**定位要求**：每一处单独给一条，`t` 原样引用 2~6 字，`ctx` 前后各 2~4 字且必须包含 `t` 并能在逐字稿里连续命中；最多 40 条。

**代码护栏（v4，2026-11-04）**：

- 词表与 LLM 走**同一套** `acceptFiller`：演绎类语气词在两条路径都拦，模型报也不收。
- 语气词只留「呃/嗯」，且段末 / 跨段 / 后接标点 / 后停 ≥0.22s 视为句末演绎，不标。
- 单字「那」只在句首（段首或前停 ≥0.12s）且后一字不是量词/时间词（个/时/里/样/些…，含繁体）时才标；「这」不收。
- 「这个/那个/那么」只看右邻：后接语气词或同类指示词才算填充；左邻是「那」不再作为判据（「那这个答题思路」会误伤）。
- `ctx` 定位优先，定位不到且全文仅一处才兜底；与词表命中去重。
- 同一份逐字稿按「算法版本+字数+首末字时间」缓存，v4 = 本次修订。

## 3. 模型不参与的决定（边界）

以下全部是确定性代码，模型无法改变：

| 环节 | 判据 | 阈值 / 取值 |
|---|---|---|
| 气口检测 | 噪声门 + 连续静音 | 均值 −6dB（钳在 −45~−25）· 最短 0.35s · 边界内缩 0.1s · 接缝保留 0.12s |

### 3.1 断句粒度：为什么不按标点加密（2026-11-04 实测）

用户问「ASR 是不是把句子合得太长、加大断句密度是不是比加护栏更好」。实测答案：**不是，加密更差。**

**① 转写本身没有"过长"，只有长尾。** 全库 109 个工程 / 3118 个句段：

| 分位 | p50 | p75 | p90 | p95 | p99 | max |
|---|---|---|---|---|---|---|
| 句段时长 | 1.84s | 2.96s | 6.02s | 8.10s | 11.99s | 23.12s |

≥7s 占 7.1%，≥10s 占 2.7%。C0853 那个 8.6s 的段落在 p90–p95 之间，属长尾不是常态。

**② 长段内部往往没有停顿可断。** C0853 首段 0.03–8.63s，内部**最大词间间隔只有 0.33s**。
paraformer 的断句来自 VAD 静音检测，没有静音就没有边界 —— 把静音阈值调到 200ms 也切不开。
且 `max_sentence_silence` / `semantic_punctuation_enabled` / `multi_threshold_mode_enabled`
这三个断句参数**只在实时接口**（paraformer-realtime-v2）上有，我们用的**文件转写 paraformer-v2 没有暴露**。

**③ 按标点做文本层细切：删除量涨三分之一，但两类错各占一半。**
同一工程、同一提示词、同一模型，只改切分粒度（20 句 → 43 句）：

| 工程 | 整段删 | 细切删 | 新增 | 取消 |
|---|---|---|---|---|
| cloud-v10-c0793 | 6 | 7 | 1 | 0 |
| ui-C0816 | 4 | 5 | 1 | 0 |
| cloud-v6-c1 | 6 | 2 | 0 | 4 |
| cloud-v10-c0777 | 3 | **10** | **7** | 0 |
| ui-C0779 | 4 | 4 | 2 | 2 |
| tb-normal | 1 | 4 | 3 | 0 |
| **合计** | **24** | **32** | **14** | **6** |

逐条审计这 14 处「新增删除」，**并非全是误删**：

| 类型 | 例子 | 判断 |
|---|---|---|
| 真漏检被补上 | tb-normal「所以记忆力好呃」卡壳后重说；「那很多人只会死劲背…那很多人只会死劲背」句内重复 | 细切做对了 |
| 真误删 | tb-normal「那牛个掌那些经验型流程心计」（ASR 乱码）；「记住才能拿分」（反问强调，不是赘述） | 细切做错了 |
| 方向搞反 | C0779 把 #14（最终完整版）的头两小句删了，却留下 #13（前面那版） | 比整段删更糟 |

所以加密不是"更准"也不是"更差"，是**把整段误删换成了碎句误删 + 偶发补漏**；
而"方向搞反"这一类是新增的错误形态 —— 整段模式下模型至少能正确判断"留后不删前"。

**④ 模型抖动大于粒度差异。** 同一工程用同一份代码重跑两次，c0777 的一次是「3 → 10 处」，
另一次是「3 → 3 处」。这类 ±1~2 的差异不能当成收益，任何"加密更好"的结论都需要多次重复才站得住。

**⑤ 误删不集中在长段。** 新增误删里 #3=3.9s、#5=5.8s、#6=5.3s、#9=4.8s，
所以"只切超长段"也躲不过（#4/#8/#10 仍 ≥7.5s，照样中招）。

**⑥ 让模型自己给删除边界也不行。** 试过在提示词里加 `del` 字段要求返回"要删的原文片段"，
C0853 六处全部返回 `"*"`（整句）—— 模型不认为句内有可分的边界。
它本来就认为整句该删，你要它划范围等于要求它换一个判断，它做不到。

**结论**：不做全局加密。粒度问题用**定点切除**解决 —— 口令分离、问句前导卡壳、slip 前缀，
都是"只删该删的那一截、其余原样保留"，比把整段打碎重判更可控，也保留了模型判断所需的完整上下文。

### 3.3 问句结构：模型判不了、标签也没有的两类（2026-11-05）

C0853 的四连问 `#10 那老师你有什么样的 → #11 那老师您这个方法在哪里学呢 → #12 你老师到底有什么方法 → #13 呃老师那到底呃呃老师你这个到底是什么方法呢`
暴露了一个空档：语义通道只有 `ok/slip/paraphrase/offtopic/filler` 五个**整段**标签，这两类句子在语义上都"成立"（是下一句的前件 / 是最终版），只能判 ok；三层确定性兜底也各有前提：

| 兜底 | 为什么接不住 #10 / #13 |
|---|---|
| 孤立设问（`run.mjs` ISO_*） | 要求 ≤0.8s 且前后都安静；#10 是 1.35s、后句只隔 0.14s |
| 短残句兜底 | 要求左右都有切口；#10 前面是 2.45s 静音，不是切口 |
| 分句悬空 | 要求「及物动词 + 数量/语气词」；「什么样的」不是 |
| inner-restart | 要求 ≥3 遍起头 + ≥5 字短语复现；#13 只有 2 遍 + 「老师」2 字，候选为 0 |

**更关键的是模型标签不稳定**：同一条 #10，11-03 16:03 那次判 `offtopic`（被 `offtopicPos` 以"中段跑题"拦下、推待确认），11-04 18:21 那次判 `ok`（理由"是下一句的前件"）——两次都不删。所以这两类不能靠语义裁决，改为**代码证明结构**：

| 判据 | 条件 | 动作 |
|---|---|---|
| 半截问句 `detectQuestionHeadFrags` | ≤12 字、句末停在「什么样的/怎么样的/哪一种的/哪个的」、0.6s 内下一句也是问句且至少长 2 字 | 整段删 |
| 问句前缀卡壳 `detectQuestionPrefixRestarts` | 段内 ≥0.35s 停顿、前缀（剥句首语气词）≤8 字且**不含疑问焦点**、后缀 ≥8 字仍是问句、两者开头连续重合 ≥2 字 | 切 `[段首, 重来点)`，后缀保留 |

全库离线扫描（34 份不同素材 / 110 个 `raw-segs.json`）：半截问句命中 **1** 处（就是 #10），前缀卡壳命中 **2** 处（#13，以及另一条素材「那我教的方法‖那我教的内容是如何去提高…」，改口重说，删得对）。

与 `offtopicPos` 的关系：不改那条护栏。它挡的是"中段整段跑题"，而这里删的是结构上残缺的一小节；命中段的 offtopic 待确认卡会因区间已被剪掉，由 `clipReviewItems` 自动剔除。

开关：`XUNJIAN_QUESTION_CUT=off`；阈值在 `rules.json → stutter.questionCut`。

### 3.4 跨句尾首重说：三个检测器都不认领（2026-11-05）

C0777 #7/#8：前句在 60.72 说了半截「…钻得进去，**相反的一个脾气**。」，停 2.22s，

这不是段内多次起头，也不是整句重说，现有三个检测器都看不到：

| `detectRetakes` | 整句相似度 **0.078**、LCP **0**；既不是整句相似，也不是"后句以前句开头" |

### 3.5 拆段视图：一个 ASR 句段里塞着「说错 + 重说」两遍（2026-11-06）

ASR 的句段是**按语义/标点切句**，不是按停顿。C0853 #3 一个句段里同时装着
「他没有方法背单词又可劳」和「不可能吧」——语义通道只能整段判 `ok`（读起来确实成立），
结构通道又要求「重来点贴段首」，两边都不认领；C0816 首段三遍起头同理。

做法是加一层**只给语义通道用的视图**，原始句段一个字不动：

| | `rawSegs` | `SPLIT.units` |
|---|---|---|
| 消费者 | 段内多次起头 / 问句前缀 / 分句悬空 / 尾首重说 / 短残句 | 语义通道（送审 + 回收 + 四道护栏） |
| 依据 | ASR 原样 | 按真实停顿再切一层 |

切点四证，缺一不切：

| 证 | 条件 | 为什么必须有 |
|---|---|---|
| 词间停顿 | ≥ `minPauseSec` 0.35s | 停顿不够的地方切开，人耳听到的是"把词咬断" |
| 声学静音 | 落在 `silencedetect` 的静音里 ≥0.10s，噪声门与剪辑同一条（`mean_volume + noiseOffsetDb`，夹 `[-45,-25]`） | 词间空隙是强制对齐的产物，实测 34 个候选里 8 个在 ±0.3s 内根本没有静音 |
| 中文词边界 | `Intl.Segmenter` 二次切分 | paraformer 的 `w` 是**字级**，不能当词表用；「我的｜孩子」这种切开就是断句 |
| 句法护栏 | 切点前不是「的/了/是/在/和/跟/把/被…」，后不是「的/了/着/过/吗/呢/吧…」 | 「孩子｜的专注」「放在｜桌子上」切开直接病句 |

噪声门必须是**每份素材自己的**：固定 `-32dB` 全库只找到 16 个切点；改自适应后 27 个
（C0816 均值 −15.3dB → 门 −25dB，固定门限在它身上几乎检不到静音）。

视图切换带来的连带改动（都是必须的，否则会出现"送审用新索引、回收用旧索引"的错位）：

- 整句级护栏一律按 `srcId` 回查原句：`offtopic` 位置窗、`closingEcho`、`DUP_HEAD`、`DANGLING` 区间包含；
- `STRUCT_ROUTE` 仍由 `detectMidRestarts(rawSegs)` 生成，送审/回收时用 `SEG[i].srcId` 映射；
- 问句识别收敛到 `question-cut.mjs` 的 `looksLikeAsk` 一份实现，`run.mjs` 里重复的 `ASK_WORD/TAG_ASK` 删掉。

开关：`XUNJIAN_SPLIT=off`；阈值在 `rules.json → split`。

### 3.6 短起头残片：拆段之后才看得见的一类（2026-11-06）

C0777 #7 的「那看到孩」0.93s 是「当孩子看到爸爸的脸是这个」的断头话。
三类判据都够不着：语义通道判 `ok`（它是后句的前件）、LCP 要求 ≥6 字连续重合、

与本刀只重叠 0.018s（同一条字边界上的取整差），旧写法把整刀吞掉，0.93s 断头话原样留在成片。

### 3.7 剪后残留审计：把「没人管」变成「有人管」（2026-11-06）

前面所有检测器都是"找得到才动手"。任何一条判据没命中，成片里就安安静静留着半截话 ——
不报错、不进日志、不进队列，事后和"这段本来就没问题"完全分不出来。
这就是用户反复遇到的「漏删」体感：不是删错，是**没有任何人认领**。

`residue-audit.mjs` 在**所有切割完成之后**对「仍完整保留（≥90%）」的单元做一遍**只读**扫描：

| 判据 | 条件 |
|---|---|
| 句内重起头 | 段首 5~6 字整短语在 4~20 字内原样再现，且再现后还剩 ≥8 字 |
| 跨句尾首相接 | 前单元尾 k 字 == 后单元首 k 字（k≥4），间隔 ≤1.5s |
| 半截起头 | ≤6 字 / ≤1.5s，后接更长单元，字覆盖率 ≥0.75 |

命中进待确认，**不改变任何已完成的剪辑结果**。

两个必须踩过的坑：

- 「句内重起头」只认 5~6 字**整短语**。放宽到 3~4 字会把排比判成口误 ——
  C0777「孩子的专注，孩子的底气，孩子遇到难题敢不敢试一试」就被误报过。
- 相邻关系必须按**完整 units 序列**取（`isLive` 标记），不能按"还剩下来的单元"取。
  C0777 里「当孩子看到爸爸的脸是这个」被删掉后，`live` 数组会让「那看到孩」和下一句
  的 gap 从 0.66s 变成 4s，直接放过 —— 但人耳听到的确实是紧挨着的两句。

开关：`XUNJIAN_RESIDUAL_AUDIT=off`；阈值在 `rules.json → split.residual`。

### 3.8 剪后极短残块：整句删了，渣还在（2026-11-06）

一段话被判整段删掉之后，剪口两侧常留下几十~几百毫秒的碎块。它不是"漏删的整句"，
也不是任何检测器能认领的对象（没有文本可判、比 `minKeptSec` 0.25s 长一点所以没被滤掉），
于是留在成片里 —— 听感是一声"咯噔"。

实测：C0777 18.53–18.79「家庭里」、19.11–19.41「最该成」（「老是…那天」被删后剩下的两个字），
成片变成「是哪个哦 / 家庭里 / 最该成 / 我觉得一个家庭…」；C0820 8.35–8.63 是一点 ASR
都没识别出来的瞬态 0.28s（低于 2.9 噪声段的 0.5s 门槛，漏网）。

两条判据任一命中即删（`rules.json → segment.crumb*`）：

- ① 区间内**没有任何** ASR 字 且 <0.40s → 噪声/换气残响；
- ② 宿主句段已被删 ≥70% 且本块 <0.50s → 那句话的碎渣。

「为什么？」这类设问短句的宿主句是整句保留的，覆盖率低，不会被误伤。实测 5 工程共清 4 处。

### 3.9 报告口径：`cuts` 不是 `segs` 的补集（2026-11-06）

验收时最容易踩的坑，记在这里免得下次重犯。`cut-plan.json` 里：

- `cuts` 只记**检测器判定的错话切口**；
- 气口（换气/静默）是另一条链路剪的（`silencedetect` → 保留段），**不在 `cuts` 里**。

两者不是互补关系。C0777 原片 117.62s、成片 72.12s，`cuts` 加起来只有 18.1s ——
剩下 27s 全是气口。只看 `cuts` 会以为"27s 被删了却没记录"，反过来只看 `segs`
又分不清那 27s 是"删了错话"还是"删了停顿"。
现在 `cut-plan.json` 同时给 `removed`（`segs` 的真实补集），`cut-audit.json` 的
`partial` 单元额外给 `keptText`（成片里**实际活下来的字**）——
只给 ASR 原文会让人把"待删的错话"误读成"成片里还有这句"。

### 3.10 段内前缀重说：两个检测器都够不着的那一档（2026-11-06）

「说了半句 → 停 0.5 秒 → 从头完整重说一遍」是最常见的口误形态，但它恰好卡在两条既有
检测器的缝里：

| 检测器 | 判据 | 为什么够不着 |
|---|---|---|
| `detectInnerRetakes` | 重来点必须在**段首 12 字内** | 这里重来点在第 21 字 |
| `detectMidRestarts` | 段内**至少 3 次**起头 | 这里是 2 次 |

飞书 #21（127.85–137.63，9.8s，全是同一个句段）：

```
那很多人只会死劲背啊  哪怕是写了很多次这个月          ← 卡在「这个月」，废稿
        ↓ 停 0.54s
那很多人只会死劲背  哪怕是写了很多次作文  依然记不住  依然不会写   ← 完整版
```

新增 `retake.mjs:detectPrefixRestarts`，五条判据缺一不删：

- ① 前缀重合 ≥ `minPrefix`(6) 字 —— 同一开头重来，不是「尾首相接」
- ② 前遍**去掉末尾 2 字**后，其余字按顺序在后遍里的覆盖率 ≥ `minCover`(0.75)
  —— 容忍语气词差异（「背啊」/「背」）和结尾改口（「这个月」/「作文」）
- ③ 后遍比前遍长 ≥ `minGrow`(4) 字（后遍才是完整版）
- ④ 前遍 ≥ `minFirstChars`(8) 字、≥ `minFirstSec`(1.0) 秒（太短是口吃，归 `detectStutters`）
- ⑤ 重来点落在 ≥ `minPauseSec`(0.30) 停顿上（真的停下来重想了）

② 是防排比/递进的核心：「我们要教孩子独立思考」对「我们要教孩子承担责任」只有 0.60，
过不了这一关。全库 100 份素材命中 3 处（飞书 #21、C0820「但是很多人只会死劲硬」、
飞书旧副本），零误报。

### 3.11 语义通道的整段删护栏⑧：一段里有重说时，不许整段删（2026-11-06）

同一个 #21，语义通道（qwen-plus）判 `paraphrase` → 删，理由写得很像回事：

> 26 句内容已被 27+28 句更完整覆盖（27 讲阅读，28 讲方法缺失），且 26 中
> 「写了很多次作文」在 10–17 句已详述，此处属冗余复述

结果一刀 9.8s，把**正确的那一遍也删了**。模型看见的是"整段"，它没法知道这段里
前半是废稿、后半是正文。

护栏⑧：只要该句命中 `detectPrefixRestarts`，语义通道对它的**整段删一律撤销**，
删哪儿由前缀重说通道给（只删前一遍）。位置在 `run.mjs` 的 `final` 落定之前。

### 3.12 碎片是怎么来的：卡片给的是"单元"不是"整句"（2026-11-06）

用户报的「整句删了却留一堆碎片」，根因不在剪辑，在**卡片的删除区间**。

旧版那张 `offtopic-mid` 卡片给的是 `[99.02,103.441] + [103.596,104.007]` 两刀，
两个端点都落在字中间（103.441 在「么」中间、104.007 在「习」中间），
用户点「删除」后成片里剩「么 / 习 / 这个」—— 正是那份碎片清单。

现在卡片一律按**整句**给（`srcId` 回查 `RAW_SEGS`）。「跑题」本来就是句子级的判断，
模型指的是整句，不是恰好落在这个拆段单元里的那半句。

同类问题一起补了两处：

- **片头提问保护**：#0「李薇老师记忆力的提升，语文成绩就能够提升吗？」被拆成
  「李薇老师」+「…吗？」两个单元，模型只看前半个，判「片头仅报人名」删掉，
  成片开场直接变成「记忆力的提升」。现在原句是问句就保留 —— 称呼是提问的一部分。
- **中段问句进卡片**：`#16「补充一点，我们的借款怎么可以怎么练习这个？」` 前后都是
  总结句、本身语义不通（ASR 把「记忆」听成「借款」），原先只因为有问号就被
  **静默保留**（连卡片都不进）。现在进 `offtopic-question` 卡片，让人拍板。

### 3.13 环境坑：`.env` 只从 HOME 读，配了 key 也可能不生效（2026-11-06）

`XUNJIAN_HOME` 指到自动化目录（没有 `.env`）时，`ai-xunjian/.env` 里的
`DASHSCOPE_API_KEY` 加载不到 → `ASR_PROVIDER` 判成 `local` → **明明在用云端 paraformer，
却按 whisper 的「长词 + 低语速」判据剪卡壳**。

症状很隐蔽：转写费用显示 ¥0.0000，同一份素材三次跑出 24 / 68 / 72 个句段（本地
whisper 与云端 paraformer 交替），而卡壳判据在 paraformer 的真实字级时间戳上会误判 ——
实测飞书「所以这个记忆力好的人」被判「语速 2.8 字/秒、单字 1.38s」，
删掉「所以这」，成片只剩「个记忆力好的人一定能够让宇文成绩变好」。

修了两层：

- `.env` 查找加回退：`HOME/.env` → `ROOT/.env`（只回退不覆盖）
- 卡壳判据的 local 分支加输入形态自检：全片最长"字" < 0.8s 说明不是 whisper 产物，
  直接返回空（宁漏勿误剪）；另加「删除段 ≥3 字」护栏 —— whisper 的 `w` 是词级，
  一个停顿就能把「这个」撑到 1.38s，按长词起点切可能只删掉「所以」这种 2 字连词。
  全库据此拦下 21 处历史误删（「李伟老师」→「老师」、「相反的一个脾气」重来版开头再删一遍）。

### 3.14 低电平整句判废：能量层的两个方向都会错（2026-11-10 实测）

气口（silencedetect）和收紧气口（逐帧掩膜）都只看能量、不看转写。同一件事的两个方向都出过：

- **整句压着音量说 → 被当静音剪成碎片。** C0793 `raw#8`「这果免费送价值一千多万就不能说是吧？」
  17 个字连续覆盖 78.02–81.40，句内窗口 p90 比语音参考低 **19.6dB**；`cut-plan.removed` 把
  字时长的 **97%** 删掉，成片只剩 `[80.31,80.42]` 0.11s「就不」。飞书 `raw#16`「补充一点，我们的
  借款…」同样，`keptText` 只剩「借款么练」（21%）。
- **句尾纯底噪 → 电平刚好卡在门限上方被保留。** DJI 结尾 89.23–90.63 共 1.39s、零个字，
  p90 比语音参考低 13.2dB，却因为 tight 门限是 `ref−18dB` 只差 1dB 而留在成片里。

**正确处理不是保护碎片，而是按整句判废、整段删干净。** 用户要的是「这句不要」，
不是「这句留三个字」。判废后整段从 `segs` 扣除，后面的 tight 与切口吸附再也碰不到它。

判据（`firstcut/speechmask.mjs`，步骤 2.6，转写之后）：

| 项 | 值 | 说明 |
|---|---|---|
| 基准 `ref` | 各句段「0.5s 分窗 p90」的**中位数** | 不用 `mean_volume`：它被大段静音拉低（DJI 全片 mean −35.5，语音 p90 −31.5） |
| 低电平整句 | `ref − 窗口p90中位数 ≥ 15dB` **且** `ref − 最响窗口p90 ≥ 9dB` | 第二条防"半句正常"；实测命中 19.6~19.9dB，未命中最高 9.0dB |
| 无字底噪 | 保留段内连续 `≥1.0s` 零字 + `p90 < ref−12dB` | DJI 实测 13.2dB；低于 1.0s 的多是正常换气 |

为什么不用 `p90−p10` 判"整句都低"：句内字间本来就有 0.15–0.3s 换气缝，p10 会被拉到 −50dB，
正常句与低电平句的跨度都是 10~15dB，该指标在 C0793 全片无区分度（第一版就是因此 0 命中）。

这类句子**不生成待确认卡片**：已经删干净了还弹一张"要不要删"只会增加噪音。

### 3.15 元话语与孤立单句：语义通道一定判 ok 的两类（2026-11-10 实测）

「单独录这一条」「没关系我就这样吧」「嗯ok我再单独录一条」在语义上都完整、通顺、语法正确，
模型只能给 `ok`；但它们是讲给录音键听的，不是讲给观众听的。

| 判据 | 条件 | 处理 |
|---|---|---|
| **孤立句** | 离「正文主体」≥5s、自身 ≤5s、所在簇跨度 ≤5s | **默认删** + 进卡告知 |
| **元话语** | 片头 2 句 / 片尾 2 句、≤4s、与相邻 3 句实词零交集、命中词表 | **只进卡不删** |

「正文主体」= 按 2.5s 间隔聚类后总时长最长的簇。C0793 #0「现在备战其中」距主体 34.5s → 孤立；
C0777 #0「那你先问呗」只差 4.53s，是正常开场 → 不标（所以 `minGapSec` 取 5.0 而非 3.0）。

两者都命中时**按孤立句处理**（先跑 isolated、`seen` 去重）：C0793 #0 既是录制说明又离正文 34.5s。

### 3.16 连续同义提问：长度不是判据，重合率才是（2026-11-10 实测）

C0853 53.3–64.4s 四句连问同一件事，每句单看都通顺，模型全判 ok：
`#10 那老师你有什么样的？` / `#11 那老师您这个方法在哪里学呢？` /
`#12 你老师到底有什么方法？` / `#13 呃…老师你这个到底是什么方法呢？`

判据（`firstcut/askchain.mjs`，步骤 2.7）：

- 两条都是问句 + 间隔 ≤2.5s；
- **焦点类别集合**（METHOD / WHERE / WHY / WHO / HOWMUCH / YESNO / WHAT）相等 + **实词重合 ≥60%**
  → 同义，删前留后，**不看长度**；
- 焦点不同但实词重合 ≥60% → 只进卡。

`#12→#13` 焦点同为 METHOD、实词重合 100% → 删 `#12`；
`#11→#12` 焦点 `{METHOD,WHERE}` ≠ `{METHOD}` → 只进卡（删了会丢掉"在哪学"这条信息）。

**`related` 必须过重合率**：初版只要求"实词有交集"，在飞书素材上出了 6 张废卡——
「接下来考什么？／考阅读理解怎么去做啊？／是瞎做吗？／作文是随便编的吗？」是设问→回答→
再设问的递进链，相邻句只共享「考／阅读／作文」这类主题词（重合 0.5）。加门槛后归零。

**必须喂 `rawSegs` 而不是拆段视图**：拆段会把 `#13` 切成「呃老师那到底呃呃」+「老师你这个到底
是什么方法呢」，两段间隔 2.59s 直接断链，正当的 `#12→#13` 反而漏判。

### 3.17 卡片一致性：区间被别的通道剪空时不许静默丢弃（2026-11-10 实测）

`review-clip.mjs` 会把卡片的可删区间与最终保留段求交。如果某句已被气口/低电平整句剪掉，
三个选项的区间都会被裁成空，旧代码 `if (!allCuts.length) { dropped++; continue; }` 直接扔掉整条，
**连日志都不打**。C0793 `raw#8` 的 `slip-noref` 卡片就是这么消失的——用户看到「模型明明标了，
界面上什么都没有」。

现在改为保留原区间、清空 `options`、标 `alreadyRemoved: true`，并在汇总行打印
「其中 N 条区间已被气口/低电平整句删掉，标为只读提示」。
